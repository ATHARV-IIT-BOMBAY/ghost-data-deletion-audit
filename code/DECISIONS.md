- **[18:31] D1 — Python 3.14, standard library first** (csv, json, sqlite3). PDFs via pypdf/poppler, already installed. *Why:* every evidence format except images can be parsed without new dependencies, which keeps the zip small and runnable anywhere. *Revisit if:* a parser needs a library we can't justify in one line.
- **[18:35] D2 — One schema module (`ghostaudit/schema.py`) owns every allowed value, the step order and the contract validator.** *Why:* the solver, prompts and scorer import the same enums, so they can't drift. *Check:* all 32 gold rows pass `validate_row`, including the canonical-order check.
- **[18:38] D3 — Scorer before solver.** `code/evaluation/main.py` scores status accuracy, row exact match, step P/R/F1 with and without evidence, position-aligned field accuracy, sequence exact + LCS order, per-operation P/R/F1, and contract violations. *Validation:* gold vs gold = 1.000 on every metric. A copy with 4 injected faults (wrong status, swapped remediation, removed COMPLETE evidence, dropped resource) was caught on all four. *Baselines to beat:* trust `reported_status` → status accuracy 0.531, step F1 0.000; always INCOMPLETE → 0.688, step F1 0.000.
- **[18:38] D4 — Fixed holdout: every 4th sample case (8 of 32), report-only.** *Why:* constants will be tuned on dev; holdout numbers are what get quoted. *Caveat:* n=8, so one case = 12.5 points.
- **[18:40] D5 — Switch S1 = string sort for resource_id.** *Why:* "ascending" on a text column; the samples can't distinguish the options. *Revisit if:* any evidence or rule text implies numeric order.
- **[18:40] D6 — No trained model.** *Why:* there are 32 labelled rows, and each answer is an evidence-linked plan over named resources, not a label from a fixed set. A trained classifier would overfit and still couldn't name resources or cite evidence. The decision logic is specified exactly (`deletion_rules.csv`, the step table), so it belongs in code. Models are used zero-shot only where reading is needed: request intent (multilingual), screenshots and PDFs, and ambiguous linking.
- **[18:42] D7 — Model provider pending; output must not depend on it.** Checked 18:35: the AWS account is reachable, but IAM user `geoai-deployer` is denied `bedrock:InvokeModel` and `ListFoundationModels` (AccessDenied in us-east-1 and us-west-2). Only a free-tier Gemini key is available. *Consequence:* the deterministic engine must produce a complete, valid `output.csv` with zero model calls. Model layers are additive, cached, and measured by ablation. *Revisit when:* Bedrock access is granted (preferred: a Claude model on Bedrock for the investigator and vision; a small model for intent).
- **[22:20] D8 — Evidence absence is scoped.** JSON snapshot bundles and SQL "inventory" captures are per-subject extracts, so a missing record there proves absence only for the people that file mentions. Topology and flat SQL dumps prove absence globally. *Why:* treating bundle evidence_51 as a full listing marked other subjects' audit records and accounts absent (status accuracy 0.969 → 0.906 before the fix, 1.000 after).
- **[22:25] D9 — Replica drift = same snapshot, primary clean, replica still exposed.** State comes from the primary copy. A replica adds a finding only in that case. *Why:* treating any replica sighting as a live copy made an old evidence_10 replica row override a later redaction (case_26). A `topology=read_replica` note on primary rows was misread as a replica, now fixed by reading the explicit `replica=` field first.
- **[22:30] D10 — Ownership vs state.** Evidence after `audit_at` may *link* a resource to the subject but never decides its state. A linked resource with no state evidence becomes a future verification check, and only in INCOMPLETE cases (switch S4). A not-found lookup proves ownership only if made on/after `requested_at`. *Why:* gold keeps future VERIFY_RECORD_PRESENT for audit records only seen after `audit_at`, and dropped account_6523 (March lookup, months before the request).
- **[22:30] D11 — Retained records can't be proven missing by inference.** For RETAIN (audit logs), only an explicit not-found counts against them. Listings taken before the deletion workflow created the record are ignored.
- **[22:35] D12 — Contact indexes are DELETE.** Log events `contact_lookup` / `contact_query` (opted-in marketing contact, legacy support contact index) map to SECONDARY_IDENTIFIER (rule_02), not analytics/support rules. Gold case_10 and case_12 confirm.
- **[22:45] D13 — Workflow linking by global elimination.** Accounts and anonymized analytics carry no identifiers; they are linked only by the case's own deletion-worker event. Measured windows: account deletion −10..80 min before `reported_at`, analytics "Policy action completed" 0..35 min. Events are assigned across all 550 requests: identifier-proven first, then any case or event with a single remaining candidate. **Ties (k cases share a `reported_at` with k events) stay unassigned rather than guessed**; that's the main remaining recall loss.
- **[22:50] D14 — Phase 1 result (zero model calls).** Samples: status 1.000; step P 0.989 / R 0.902 / F1 0.943; row exact 0.500; dev F1 0.948, holdout F1 0.927. - **[23:05] D15 — Gemini over REST with the standard library (`ghostaudit/llm.py`).** No SDK dependency. `responseSchema` constrains output, so malformed JSON is an API failure, not a parsing guess. Retries only for 408/429/5xx/network (backoff + jitter, max 4); auth and bad-request errors fail at once. Every call is counted (`USAGE`) and written to `code/evaluation/last_run_usage.json`, which feeds `usage_report.md`. Model configurable via `GEMINI_MODEL` (default `gemini-2.5-flash`, free tier). *Why not Bedrock:* IAM denies InvokeModel (D7).
- **[23:05] D16 — Vision transcribes, code decides (`ingest/media.py`).** The model returns resource ids, identifiers and verbatim status text, never a policy state. `_state()` maps status words to observed states. Ids must match a known resource family and identifiers must parse, otherwise they're rejected and reported. Answers are cached by sha256(image + prompt version), so reruns cost zero calls and the shipped cache reproduces offline. With no key and no cache, screenshots are skipped and listed as ingest problems, and the run still completes. `--no-models` gives the deterministic-only ablation.

- **[22:35] D18 — Measured vision failures and the guards they produced.** The first pass over 11 screenshots (11 calls, 15.5K in / 1.9K out tokens) returned `audit_record_1..6` for on-screen `audit_record_001..006` (leading zeros dropped) and invented `marketing_4` for `marketing_001`. The second pass got the audit ids exact; escalation recovered `marketing_001`. Total for Phase 2 development: 26 calls; final cache serves all 11 images with 0 calls.
